1. Mise à jour 3.4 → 3.5

Tu gardes ton Render actuel, ton URL et ta base PostgreSQL.
Backup
PiChat → Admin → Sauvegardes → crée une sauvegarde.
Ouvre le bon dépôt
GitHub Desktop → Repository → Show in Finder.
Remplace le code
Copie le contenu du dossier PiChat_v3.5_PERFORMANCE dans ce dossier GitHub. Choisis Remplacer.
Commit + Push
Message conseillé : PiChat 3.5 PERFORMANCE. Puis Push origin.
N'envoie pas venv. Render réinstalle les dépendances avec requirements.txt.

2. Render

Après le Push, Render détecte automatiquement le commit et redéploie pichat-free-online. Attends l'état Deploy live.

Ne crée pas un nouveau Blueprint. La migration 350001 est appliquée au démarrage sur la base existante.

3. Première ouverture

PiChat 3.5 utilise un nouveau cache PWA pichat-v3-3500. Il supprime les caches précédents afin d'éviter le problème d'interface brute rencontré en 3.4.

Ouvre ton URL Render habituelle.
Si Safari garde une ancienne page, fais une fois ⌘ ⇧ R.
Reconnecte-toi avec ton propriétaire existant. Il ne faut pas refaire /setup.

4. Ping PERFORMANCE

Dans le chat, PiChat mesure en priorité le RTT du WebSocket, sans requête PostgreSQL. Si le WebSocket n'est pas actif, /api/ping sert de solution de repli.

≤ 50 ms objectif atteint
51–110 ms correct
>110 ms élevé
50 ms est un objectif, pas une promesse. La distance jusqu'au datacenter, le Wi‑Fi/4G/5G et le réveil éventuel de l'hébergeur influencent aussi le résultat.

5. Checklist

6. À ne surtout pas faire

  • Ne supprime pas pichat-db.
  • Ne recrée pas le service Render.
  • Ne change pas PICHAT_SECRET_KEY.
  • Ne publie pas .env, des clés API, des backups privés ou une base SQLite réelle.
  • Ne remets pas venv/ sur GitHub.

7. Dépannage rapide

GitHub Desktop ne voit rien

Utilise obligatoirement Repository → Show in Finder puis copie les fichiers 3.5 dans le dossier qui vient de s'ouvrir. C'est ce dossier précis qui est suivi par GitHub Desktop.

Ancienne interface

Recharge une fois avec ⌘ ⇧ R, ou ferme/réouvre l'onglet. Le service worker 3.5 nettoiera ensuite les anciens caches.

Render échoue

Vérifie que le Dockerfile contient PYTHONPATH=/app:/app/backend. Cette correction est déjà incluse dans la 3.5.
